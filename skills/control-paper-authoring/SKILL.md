# 控制论文作者写作

以作者身份把已有研究写成论证清楚的论文。主入口只确定任务、领域配置与模块；具体写作规范各有一个维护位置。

## 任务与事实边界

- 提取目标语言、材料、允许改动的范围和指定主稿；不重复询问已有明确答案。已有稿件的“润色”“去 AI 味”默认只改语言，不重设方法、数据或结构。
- 以材料和作者确认的事实为依据，保留公式、符号、统计口径、引用关系与必要条件。明确的范围过度可以收缩，例如材料足以支持“已测试工况均优”时将“所有工况均优”改为该表述，并在修改说明中列出。无法确定证据是否充分或作者意图时，先询问再改主张；涉及关键不利结果时仍先按 M02 询问。
- 不利结果按 M02 取舍；影响核心结论或关键比较时先询问作者，继续处理无关部分。不得捏造、改算或通过隐瞒关键事实制造支持。
- 内部待办、改稿答复和核查过程留在正文外。缺项不写成已完成工作；不承诺录用或通过 AI 检测。

## 选择领域与模块

控制与机器人任务默认读取 [控制领域配置](profiles/control.md)。用户指定其他领域时，从[配置索引](profiles/index.md)选择；没有对应配置时询问所需适配，不能静默沿用控制专业规则或宣称支持尚未创建的领域。

配置为每个模块指定唯一主规则文件，以及明确登记的扩展 skill。下面只定义职责和触发条件，不重复各模块正文。

| 模块 | 职责 | 何时读取 |
| --- | --- | --- |
| M01 | 论文章节安排 | 起草章节、组织整稿、重组或压缩结构 |
| M02 | 作者叙事与结果取舍 | 所有论文写作、改写、翻译、压缩和结构组织，动笔前读取 |
| M03 | 去 AI 味与自然表达 | 起草后的语言整理、润色、翻译或明确的去 AI 味任务 |
| M04 | 论文常用句式 | 需要领域句式，尤其英文定义、推导、方法与结果表达 |
| M05 | 常用词汇与使用场景 | 术语选择、搭配、翻译或含糊词义；不宣称已有词频统计 |
| M06 | 技术含义与证据 | 技术或统计内容起草、实质修订，或发现相应语义疑点 |
| M07 | 仿真与实验叙事 | 安排验证、对比、消融、结果解释和正文数字 |
| M08 | 图表、文献与交付 | 图表说明、格式、引用、匿名、文件编辑和交付检查 |

按当前配置解析模块间的 Mxx 引用，再读取实际文件；不从目录扫描所有技能。先读所用 skill 的 SKILL.md，参考资料按需读取，当前上下文完整读过的版本不重读。文件不可用时说明缺少哪部分，并继续不依赖它的工作；不自动安装。

模块规则受任务范围、真实研究内容和当前配置约束。领域术语及模板优先于通用文风建议；明确登记的适配规则决定如何使用配套 skill。未处理的冲突先询问作者，不按加载顺序覆盖。开始写作时在正文外简述实际使用的技能。

## 写作与交付

围绕问题、方法和证据组织材料。只改已识别的问题，不为统一句长、替换同义词或增加变化而重写正确表达。交付前按篇幅核对作者口吻、术语句式和含义守恒；文件、引用及版式检查遵循 M08 与宿主要求，报告实际完成范围。

返回可用正文或修改指定文件。用户要求对照时列“位置、原句、具体问题、新句”，真实矛盾与关键缺项另列。

## 维护入口

修改模块、接入新 skill 或增加领域配置时读取[维护与扩展约定](references/maintenance.md)，每次实际改动更新 [CHANGELOG.md](CHANGELOG.md)。日志和来源记录不属于日常写作必读文件。
